## Identity & context
Bloat Guardian is a web app for Product Owners, TPMs, and individual builders to analyze agentic coding repositories for waste, token bloat, duplicated agent instructions, oversized context files, and review inefficiency, then return a quantified, plain-language efficiency verdict with actionable savings recommendations.

## Core flow
Stage 1: Intake
- User starts a new scan from one of 2 sources:
  - GitHub repository import
  - Bitbucket repository import
  - Manual upload of a `.zip` file
- Accept repositories up to 1,500 files or 250 MB compressed, whichever limit is reached first.
- Accept these file types for analysis:
  - `.md`
  - `.txt`
  - `.json`
  - `.yaml`
  - `.yml`
  - `.mmd`
  - `.ts`
  - `.tsx`
  - `.js`
  - `.jsx`
  - `.py`
  - `.go`
  - `.java`
  - `.rb`
  - `.rs`
  - `.cs`
- Give special classification to likely agent-related files by filename or path match:
  - `*.agent.md`
  - `instruction.md`
  - `instructions.md`
  - `orchestrator.md`
  - `workflow.md`
  - `context.md`
  - `prompt.md`
  - `memory.md`
  - `system.md`
  - `/agents/`
  - `/skills/`
  - `/prompts/`
  - `/context/`
  - `/memory/`

Stage 2: Repository parsing
- Extract repository tree, file metadata, file sizes, line counts, token estimates, and path categories.
- Build a file inventory grouped into:
  - Agents
  - Skills
  - Context and memory
  - Prompt and orchestration
  - Source code
  - Diagrams
  - Other text assets
  - Docs
- Mark files as scanned, skipped, unsupported, binary, or oversized.
- Skip any single file larger than 5 MB for content parsing but still include metadata in the report.
- If archive extraction fails, stop the scan and show `ImportFailed`.

Stage 3: Adversary scan
- Run heuristic analysis across 5 score categories:
  - Redundancy
  - Token bloat
  - Review overhead
  - Agent sprawl
  - Architecture inefficiency
- Detect and quantify:
  - Near-duplicate files by text similarity
  - Repeated instruction blocks across agent and context files
  - Oversized context files
  - Overlapping agent responsibilities
  - Excessive number of orchestration layers
  - Excessive and repetitive skills files
  - Monolith vs microservice mismatch signals
  - Review loop overhead inferred from duplicated review instructions and multi-stage approval chains
- Produce issue records with severity, evidence, impacted files, estimated token waste, and estimated credit waste.

Stage 4: Verdict generation
- Create a weighted overall efficiency score from 0 to 100.
- Return an efficiency verdict enum:
  - `Lean` for score 80-100
  - `Watchlist` for score 60-79
  - `Wasteful` for score 40-59
  - `Critical` for score 0-39
- Summarize top 5 waste drivers in non-technical language.
- Show transparent savings assumptions and formulas.

Stage 5: Recommendation drafting
- Generate recommendations for each issue type with:
  - Expected impact enum: `Low`, `Medium`, `High`
  - Effort enum: `Small`, `Medium`, `Large`
  - Estimated token/credit reduction
  - Estimated dollar savings
- Draft replacement content for up to 25 files total across:
  - `instruction.md`
  - `instructions.md`
  - `orchestrator.md`
  - `context.md`
  - `memory.md`
- Drafts must be copyable in-app and downloadable as a `.zip`.

Stage 6: Share and export
- Allow the user to:
  - Download updated md files for agent/skills/instructions
  - Download full report as PDF
  - Download redacted report as PDF
  - Download findings as CSV
  - Download recommendation drafts as `.zip`
- Redacted report must remove file contents and replace exact file names with path aliases while preserving counts, score, category findings, and savings estimates.

Stage 7: History
- Keep the last 10 scans for the single user.
- Show scan date, source, repo name, branch if present, overall score, verdict, files scanned, files skipped, and estimated savings.

## Rules
- Single-user app only. No team workspace behavior.
- A scan is valid only if at least 5 text files are parsed successfully.
- If fewer than 5 text files are parsed, mark scan status `InsufficientData` and do not calculate savings.
- Token estimation rule:
  - Estimate tokens as `ceil(character_count / 4)`
  - Show this formula in the report
- Overall score weighting:
  - Redundancy: 25%
  - Token bloat: 25%
  - Review overhead: 20%
  - Agent sprawl: 20%
  - Architecture inefficiency: 10%
- Category scores are integers from 0 to 100.
- Score penalties:
  - Duplicate or near-duplicate agent/context file pair with similarity >= 0.80: minus 5 points each, cap 32 per scan
  - Repeated instruction block >= 150 characters found in 3 or more files: minus 4 points each, cap 20 per scan
  - Context or memory file estimated over 8,000 tokens: minus 6 points each, cap 24 per scan
  - More than 12 agent-like files in repo: minus 2 points per additional file, cap 20 per scan
  - More than 4 review/approval stages inferred from instruction text: minus 5 points, cap 15 per scan
  - Microservice mismatch signal: if service directories >= 8 and total non-generated source files < 120, minus 12 points
  - Monolith mismatch signal: if 1 service and 10 or more agent role files with overlapping responsibilities, minus 10 points
- Near-duplicate detection:
  - Use normalized text similarity on supported text files
  - Ignore whitespace-only changes
  - Ignore case-only differences
- Oversized file handling:
  - If file size > 5 MB, do not parse content
  - Mark as `SkippedOversized`
  - Include file path, size, and skipped reason in the report
- Unsupported file handling:
  - If file extension is not supported, mark as `SkippedUnsupported`
- Partial scan handling:
  - If 1 or more files are skipped, surface a visible warning banner with file count and reasons
  - If more than 20% of files are skipped, append `PartialScan` badge to the final verdict
- Savings model:
  - For each issue, estimate monthly token waste using issue-specific formulas
  - Convert token waste to credits using a configurable default ratio of 1 credit per 100,000 tokens
  - Show both token and credit estimates and all assumptions
  - Aggregate savings must show low and high range using +/-20% variance
- Recommendation generation rules:
  - Only generate draft replacement content for files classified as agent, orchestration, instruction, context, or memory
  - Do not generate replacement content for source code files
- Report plain-language rule:
  - Every finding summary must be readable at approximately grade 8 level
  - Avoid unexplained jargon in summary cards
- Download rules:
  - Full report PDF maximum 40 pages
  - Redacted report PDF maximum 25 pages
  - CSV export includes one row per issue
- Data retention:
  - Keep uploaded zip contents and imported repo content for 7 days maximum
  - Keep derived scan metadata and reports for 30 days
- Privacy warnings:
  - Before import, show a checkbox acknowledgment: `I confirm I have the right to analyze this repository content`
  - User must check it before scan starts

## Roles & access
Single role: User
- Can connect a GitHub repository
- Can upload a `.zip` repository export
- Can upload the .md files 
- Can start, view, and delete scans
- Can view all findings and all generated drafts
- Can download full, redacted, and CSV reports
- Can trigger VS Code handoff flow
- Can see skipped file warnings and partial scan status

## Integrations
### GitHub import
- Support public repositories in version 1.
- Input is a GitHub repository URL and optional branch.
- Fetch repository archive and metadata.
- Error handling:
  - If repo is not reachable, show `GitHubRepoUnavailable`
  - If rate-limited, show `GitHubRateLimited` and instruct user to retry in 15 minutes
  - If archive download exceeds 250 MB, stop import and show `RepoTooLarge`
  - If branch does not exist, show `BranchNotFound`
- Fallback:
  - Offer manual zip upload on every GitHub import failure state

### VS Code handoff
- First version does not edit files in place.
- Generate local-export package and an `Open in VS Code` helper flow.
- Error handling:
  - If browser cannot launch local URI, show manual instructions and still allow download
- Fallback:
  - Always provide downloadable handoff package even if local open fails

### File upload
- Accept `.zip` or `.md` only.
- Error handling:
  - If zip is corrupted, show `ZipCorrupted`
  - If zip exceeds 250 MB, show `ZipTooLarge`
- Fallback:
  - Let user re-upload without losing scan settings

### PDF and CSV export
- If PDF generation fails, allow HTML print view as fallback
- If CSV generation fails, allow issue table copy-to-clipboard as fallback

## Out of scope
- Multi-user collaboration
- Role-based permissions beyond a single user
- GitHub write-back or pull request creation
- Direct file editing inside VS Code
- In-place code modification in repositories
- Private GitHub repository authentication
- SSO, OAuth account linking beyond the minimum needed for public repo import
- Payment processing, subscriptions, and billing
- Real-time collaborative comments
- Model fine-tuning
- Source code quality linting unrelated to agentic efficiency
- Security auditing, secret scanning, license scanning, or dependency vulnerability analysis
- Running arbitrary code from imported repositories
- Native desktop or mobile apps
